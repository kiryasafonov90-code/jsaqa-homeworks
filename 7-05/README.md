# Домашнее задание 7.5 — Puppeteer 2

Автотесты бронирования билетов в учебном приложении «Идём в кино».

## Установка

Требуется Node.js 20+.

~~~bash
cd 7-05
npm install
npx puppeteer browsers install chrome
~~~

По умолчанию тесты используют http://qamid.tmweb.ru/client/index.php.
Адрес можно переопределить через переменную окружения BASE_URL.

## Задание 1 — Puppeteer

Запуск: npm run test:puppeteer

Три теста:
1. Happy path: выбрать одно свободное место и проверить его в предварительном билете.
2. Happy path: выбрать два свободных места и проверить их в предварительном билете.
3. Sad path: не выбирать места и проверить, что кнопка бронирования неактивна.

Для тестов используются Jest hooks beforeEach / afterEach, Page Object и короткие команды.

## Задание 2 — Puppeteer + Cucumber

Запуск: npm run test:bdd

Те же три сценария описаны в features/booking.feature.
Шаги находятся в features/step-definitions/booking.steps.js,
хуки браузера — в features/support/hooks.js.

## Проверка

Оба набора: npm test

Для запуска с видимым браузером в Linux/macOS:

~~~bash
HEADLESS=false npm test
~~~

В Windows PowerShell:

~~~powershell
$env:HEADLESS='false'
npm test
~~~

В тестах используется день 2 и сеанс 1. Если расписание стенда изменится,
значения можно поменять в константах DAY и SESSION файла tests/booking.test.js
и в Предыстории файла features/booking.feature.

Тесты доходят только до предварительного подтверждения и не нажимают
кнопку получения кода бронирования.

## Исправление замечаний преподавателя

Метод openSession(day, session) выполняет одну навигацию:
1. Открывает расписание.
2. Выбирает день.
3. После выбора дня получает актуальный список сеансов.
4. Открывает указанный сеанс и дожидается схемы зала.

Нет циклов с повторной перезагрузкой страницы, поэтому старые ссылки
на элементы сеансов не используются. После открытия зала метод сразу
возвращает управление следующему шагу, который выбирает места на этой схеме.
